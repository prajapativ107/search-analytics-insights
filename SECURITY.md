# Security Policy

We take the security of SearchLens seriously. If you believe you have found a security vulnerability, please read this document to understand how to report it responsibly.

---

## Supported Versions

Only the latest stable version of SearchLens is supported with security patches. If you find a security issue, please ensure you can reproduce it on the latest release before reporting.

| Version | Supported |
| :--- | :--- |
| **1.0.x** |  Yes (Active Support) |
| **< 1.0.0** | ❌ No |

---

## Reporting a Vulnerability

**Please do not report security vulnerabilities via public GitHub issues.**

If you discover a security vulnerability in SearchLens, report it privately to the plugin maintainer:

* **Email**: **prajapativ107@gmail.com**
* **Format**: Please include the following details in your report:
  * A detailed description of the vulnerability.
  * Steps to reproduce the issue (including PoC code or payloads if applicable).
  * Impact of the vulnerability (what can an attacker achieve?).
  * Any suggestions for mitigation or patching.

We will review your submission and contact you within the response timeline.

---

## Response Timeline & Disclosure

* **Initial Triage**: We aim to acknowledge receipt of your report and provide an initial assessment within **48 hours**.
* **Remediation**: Once verified, we will work on a patch. We target releasing a security fix within **7 to 14 days** of triage, depending on complexity.
* **Public Disclosure**: Once a patch is released, we will coordinate public disclosure (via changelogs and WordPress.org release notes). We request that you do not disclose the vulnerability publicly until a patch has been published and made available to users.

Thank you for helping keep our users safe!
